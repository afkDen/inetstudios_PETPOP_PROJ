# Frontend / UI Design Skills — v8.2

The reusable bootstrap includes a small Roblox-adapted frontend stack. It is generic bootstrap capability; it does not encode any external project's Issue/PR history.

## Bundled adaptations

- `impeccable-ui` — hierarchy, design systems, typography/spacing, critique and polish inspired by reviewed Impeccable/frontend-design guidance. It explicitly does not force flat/minimal web styling; dimensional, illustrated, textured game UI remains first-class.
- `interaction-motion` — tactile feedback, timing/easing, interruptibility and reduced-motion guidance adapted to Roblox motion primitives.
- `design-taste` — anti-generic visual direction, controlled alternatives and reference transformation without fabricated evidence.
- `roblox-frontend-systems` — Roblox-native GuiObject/layout/input/safe-area/state/performance/trust-boundary guidance, informed by reviewed open Roblox UI/UX skills.

## Routing

`creative-director` owns visual-system direction, `frontend-worker` turns approved direction into responsive Roblox GUI/HUD, and `assurance-reviewer` uses `EXPERIENCE` mode for fresh visual/UX review. The Lead loads these only when the task needs them.

Real acceptance still requires actual state binding and real Studio/device evidence where applicable.

## Provider-neutral visual workflow

No frontend task requires Claude Design specifically. `visual-design-orchestration` binds `design.visual` to the strongest real capability exposed by the active runtime. BloxUI may accelerate blueprints/prototypes, but Fusion/BloxUI runtime adoption is a human architecture decision.
