# BloxMaps / BloxUI Accelerator

BloxUI is **optional acceleration**, not the canonical visual-design system. The bootstrap must remain equally usable with Claude, OpenAI/Codex, Gemini, Cursor, Copilot, or other capable agents.

Use it when declarative blueprints, rapid prototypes, settings/utility screens, screen-state inventories or responsive layout experiments save time.

Do **not** silently make Fusion 0.3/BloxUI the game's frontend architecture. Runtime adoption is a human architecture gate. For signature HUD/main-menu/collection surfaces, approved custom art direction and the project's frontend system remain authoritative.

Preferred uses:
- generate or hand-author a blueprint as a disposable/inspectable prototype;
- borrow schema ideas for screens, HUD, states, actions and responsive coverage;
- run normalization/lint ideas against a design;
- compare prototype variants rapidly.

Avoid:
- adding unrelated shop/pass/RNG/trading screens merely because the schema supports them;
- copying BloxUI's predefined archetypes as final identity;
- requiring the hosted BloxMaps server or Claude/OpenAI keys;
- claiming a blueprint render is live Studio evidence.

When a project explicitly approves BloxUI runtime adoption, record that architectural decision, dependency/license implications and migration boundary before implementation.
